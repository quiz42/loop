# Command: /loop:refine-plan

Refine an annotated implementation plan and produce a QA ledger that records how every reviewer comment was handled. Use this command after reviewers add `CMT:` blocks, `<cmt>` blocks, or `<comment>` blocks to a plan generated by `/loop:gen-plan`.

## Usage

```
/loop:refine-plan --input <path/to/annotated-plan.md> [options]
```

Internally validates paths with:

```
loop refine-plan --input <path/to/annotated-plan.md> [--output <path/to/refined-plan.md>] [--qa-dir <path/to/qa-dir>] [--discussion|--direct]
```

## Options

| Option | Default | Description |
|--------|---------|-------------|
| `--input FILE` | required | Path to the annotated plan containing reviewer comment blocks |
| `--output FILE` | input file | Path for the refined plan; when omitted, the input plan is refined in place |
| `--qa-dir DIR` | `.loop/plan_qa` | Directory where the QA ledger is written |
| `--alt-language LANG` | config value | Optional translated output language for plan and QA variants |
| `--discussion` | config value | Ask clarifying questions for ambiguous comment handling |
| `--direct` | config value | Make minimal conservative assumptions without interactive discussion |

## Comment Formats

`refine-plan` supports inline and multi-line comments in these formats:

```markdown
CMT:
Clarify whether this task depends on the schema migration.
ENDCMT
```

```markdown
Text before <cmt>clarify this acceptance criterion</cmt> text after
```

```markdown
<comment>
Research whether the command should preserve legacy configuration keys.
</comment>
```

Comment markers inside fenced code blocks or HTML comments are ignored. Empty comment blocks are removed but do not create QA ledger entries.

## What It Does

1. Validates that the input plan exists, contains required plan sections, and has at least one non-empty reviewer comment block.
2. Classifies each comment as a question, research request, change request, or deferred decision.
3. Removes comment markup from the refined plan.
4. Applies clear plan edits for accepted change requests.
5. Writes a QA ledger under `--qa-dir` with a comment ledger, answers, research findings, applied changes, remaining decisions, and refinement metadata.
6. Writes translated plan and QA variants when `--alt-language` is a supported non-English language.

## QA Output

For an input plan named `plan.md`, the default QA path is:

```
.loop/plan_qa/plan-qa.md
```

The QA document includes these sections:

- `## Summary`
- `## Comment Ledger`
- `## Answers`
- `## Research Findings`
- `## Plan Changes Applied`
- `## Remaining Decisions`
- `## Refinement Metadata`

## Examples

```
# Refine a plan in place and write QA output to .loop/plan_qa
/loop:refine-plan --input docs/plan.md

# Write the refined plan to a new file and store QA in a custom directory
/loop:refine-plan --input docs/plan.annotated.md --output docs/plan.refined.md --qa-dir docs/plan-qa

# Run in direct mode and create Spanish translated variants
/loop:refine-plan --input docs/plan.md --direct --alt-language es
```

## Expected Output

```
[loop] Reading annotated plan from docs/plan.md
[loop] Found 4 reviewer comment blocks
[loop] Wrote refined plan to docs/plan.md
[loop] Wrote QA ledger to .loop/plan_qa/plan-qa.md
```
